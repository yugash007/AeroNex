## Defects found and fixed

Each fix had a failing run first. Logs are in the T15 scratch folder (list at the end).

1. **Voice STOP spotter missed "stop" (spec 4.12, Vosk path).** Evidence: the T14 emulator bench (en and te MISS) and the T14 host replay of the gate. The Vosk stop partial came 420-520 ms after the word, so the second consecutive partial landed after the 600 ms hangover and the gate stopped feeding. **Fix:** `StopSpotter.endSegment()` (default `false`). `SpotterGate` calls it when a segment's hangover runs out, and a `true` counts as a detection. `VoskStopSpotter` decodes the part step, then `finalResult()` goes through `StopTokenRule.final` (the backstop). Tests: 3 in `SpotterGateTest`, 2 in `VoskGrammarEngineTest`; red was a compile failure. Bench re-run (EMULATOR): vosk-en **HIT**, 0/6 false fires. hi and te still **MISS**, but the cause is the audio: a host replay with the segment-end final result gives उठो for the hi eSpeak "रुको" and an empty result for the te eSpeak "ఆపు" (v0 voice). Real speakers are needed (spec 10.2).
2. **The release app could not install the sherpa speech packs.** `ModelPackStore.import` was called only by the debug bench, so a release phone had no way to get Tamil/Kannada/Malayalam voice or the keyword spotter. **Fix:** `ModelPackStore.importWaiting(packs, failed)`. At every voice start, `AndroidVoiceEngines` verifies and copies in packs whose import folder is complete: that language's CTC pack and the KWS packs. A pack that fails is skipped for the rest of the process. Tests: 2 in `ModelPackStoreTest` (red: unresolved reference). Emulator: the installed KWS pack was moved aside, and the next voice start re-imported it from `files/import`.
3. **Missing licence notices** (T13 review). sherpa-onnx (Apache-2.0) and ONNX Runtime (MIT) ship in the APK; the IndicConformer (MIT, AI4Bharat) and GigaSpeech KWS (Apache-2.0) models run in it. **Fix:** `app/assets/licenses/{sherpa-onnx,onnxruntime,indicconformer}.txt`, `registerLicenses()` in `main.dart`, and the asset list in `pubspec.yaml`. Test: `test/licenses_test.dart` (red: method not found). All four notice files are in every APK, and the Licenses screen lists them.
4. **Flaky JVM test.** In the first full run, `VoiceSessionTest.rejectionsAreShownAndRepeatedUnclearAnswersDegradeVoice` failed with "expected UNSURE but was null". The test read the status after the engine's finish count rose but before the speech thread published the parse, and the first parse in a process takes about 100 ms. **Fix (test only):** wait for the published outcome. The app code is unchanged.
5. **Dead `--codec` path in `tools/check_sitl.py`** (T13 review). It drove the deleted `check_mavlink_native`. It is removed, and the script is now pymavlink-only. `tools/simulation/check_gazebo.py`, which `aeronex_sim.py --self-test` runs, imported `NativeCodec` from it, so it now encodes and decodes with pymavlink. The decoded fields are the same as the removed C codec's. After the change, the self-test passed, and `check_sitl.py` passed against its own disposable ArduCopter SITL in WSL (heartbeat, stream requests ACKed, 3 m takeoff, LAND ACKed).

## SITL

Headless Gazebo SITL. This run's simulator was slower than in earlier waves: **0.61-0.64x real time**, with a heartbeat interval of 1.5-1.7 s.

- **Self-test** (`aeronex_sim.py --headless --self-test`, pymavlink): PASS. Max altitude 3.04 m, position error after the 2 m move 0.037 m, 75 s.
- **SupervisorSitlTest, 11/11 pass:** takeoff/move/land; STOP on the ground → non-forced disarm; STOP during the arm round trip (DISARM ACK 9.9 ms, no takeoff follows); in-air non-forced disarm refused; STOP mid-move → BRAKE; Cancel = STOP; external mode change → UNKNOWN; home-distance rejection (at 23.9 m from home); GPS-denied BRAKE refused → LAND.
- **LinkSessionSitlTest, 1/1 pass.** It needs `AERONEX_SITL=1` as well as `-Psitl=1`, so it was skipped in the first SITL run and passed in the second.
- **SessionControllerSitlTest is flaky on its last assertion.** The assertion is the plan's extra wall bound: M2 wall p95 ≤ the median echo-stream period + 60 ms.
  - T15 run 1: **fail**. p95 378.3 ms against a bound of 375.1 ms (period 315.1 ms), at speed 0.635.
  - T15 run 2: **fail**. p95 395.2 ms against a bound of 388.9 ms (period 328.9 ms), at speed 0.643.
  - Review re-run, 2026-10-14 22:15-22:21, headless Gazebo SITL, `-Psitl=1` and `AERONEX_SITL=1`: **pass, 13/13** (LinkSession 1, Supervisor 11, SessionController 1).
    - p95 364.0 ms against a bound of 390.9 ms (period 330.9 ms + 60), at speed 0.604.
    - At real time: p50 196.8 / p95 220.0 ms.
    - STOP → BRAKE ACK through the controller: 6.6 ms.
    - Supervisor STOP → BRAKE ACK: p50 3.9 / p95 6.3 ms (n = 10).
    - Source: the JUnit XML that run left in `app/build/app/test-results/testDebugUnitTest/`.
  - **Spec M2 itself passes in all three runs.** At real time the p95 is 240.1 / 254.3 / 220.0 ms against a target of ≤ 300 ms (p50 199.5 / 217.8 / 196.8 ms).
  - The app side is unchanged: confirm → move frame p50 0.24 / p95 0.30 ms.
  - Margin of wall p95 over the stream period, against the 60 ms allowance:
    - T8c: 10 and 34 ms;
    - T15: 63 and 66 ms;
    - review re-run: 33 ms.
  - The margin depends on ArduCopter's scheduling jitter in wall time at the simulator's current speed (0.60-0.76x on this host). The bound is therefore borderline on this host: a failure is not evidence of an app regression.
  - Everything else in the test passed before that assertion in every run: takeoff, four five-step plans, STOP → BRAKE (ACK 5.5 / 30.9 / 6.6 ms) and land.
  - The bound was not loosened. Follow-up: scale `WALL_MARGIN_MS` by simulator speed in a later task.

## Emulator end-to-end against Gazebo SITL

The x86_64 debug build was installed over the T14 build (`adb install -r`; models kept). The saved link was UDP `10.0.2.2:14550`, local port `14551`, Wi-Fi profile, unsigned. Screenshots and the command trace from the MAVProxy tlog are in the scratch folder.

1. Launch: the app auto-connects in dry run and shows "Connected · Stabilize (Pilot mode) · Alt 0.0 m · Dry run · Unsigned link".
2. Link setup → **Fly the drone** → notice → On.
3. Tap pad **Take off**, 3 m → "1. Take off to 3 m" → **CONFIRM** → COMPLETED. The status line shows "Guided (this app) · Alt 3.0 m". Confirm → in the air took 12.6 s.
4. Typed **"go forward 5 meters and move right 3 meters"**, sent through `submitText` and parsed by the Kotlin parser → "1. Move forward 5 m, 2. Move right 3 m" → **CONFIRM**. The on-screen **STOP** 2.5 s later gave "STOP confirmed: BRAKE" and "Brake (this app)". Step 1 shows UNKNOWN (interrupted by STOP) and step 2 "SKIPPED — not sent". The tlog has exactly one move frame (frame 9, 5 m), then DO_SET_MODE BRAKE, ACKed 3 ms later.
5. **Volume-Down** while already in BRAKE sent a new BRAKE, which was accepted with no mode change (as in T8c).
6. Tap pad **Forward 3 m** → **CONFIRM** → **Volume-Down mid-move**. The mode went Guided → Brake (this app). The last STOP shows trigger VOLUME_DOWN, action BRAKE, CONFIRMED. The tlog ACK came 4 ms after the command.
7. **Push-to-talk.** Holding the Talk bar for 2.5 s and long-pressing Volume-Up each ran one utterance through the service: AudioRecord VOICE_RECOGNITION in the foreground service, `PttUtterance`, and Vosk te, then en. Both answered "Nothing was recognised. Say the command again." (pttUp → final p50 68.3 / p95 84.2 ms, n = 2).
   - The emulator microphone delivers digital zeros. After 500 ms of zeros the app's silenced-capture detector says "Another app is using the microphone, so voice is off", although Android reported the recording "not silenced".
   - **No spoken command could be injected into the emulator microphone.** Recognition was therefore checked through the debug bench (below), which plays eSpeak clips into the same capture ring, `PttUtterance`, engines, `SpotterGate` and parser, but not through AudioRecord.
8. **Language picker** lists Indian English, Hindi, Telugu, Tamil, Kannada and Malayalam. The Models screen shows en/hi/te "Ready" and ta/kn/ml "Coming in the next update". On this Tier L AVD, choosing Tamil keeps the "voice is off" line, because the silenced-microphone message outranks the "needs a phone with 4 GB" reason. The tier refusal itself is covered by `EnginePolicyTest` and the T14 bench.
9. Tap pad **Land** → **CONFIRM** → COMPLETED, Alt 0.0 m.
10. **Licenses:** sherpa-onnx, ONNX Runtime and GigaSpeech keyword spotter model are listed. All four notice files are in every APK.
11. **logcat:** 80,998 lines, **0 FATAL**, 0 ANR, including the bench re-run. The emulator and SITL were stopped afterwards.

## Open caveats

- **No real low-end phone measurements.** Reference phones R0-R5 are pending. The spec 6.2/6.3 Tier gates (memory cap, A53/armv7 CTC RTF ≤ 0.15) and the G1 latency targets stay open. Every speech number here and in T14 is EMULATOR or host. Nothing ran on armv7 or on any arm64 device.
- **Indic accuracy has been measured only on synthetic eSpeak NG clips.** The hi and te voice STOP missed on them, and Tamil CTC was only benchmarked. The hi/te/ta/kn/ml grammar tables are provisional until a native speaker reviews them (T9/T10).
- **zh-en KWS licence unconfirmed.** The `kws-zh-en-3M-chunk-8` pack is off by default; the shipped default is GigaSpeech 3.3M chunk-16 (Apache-2.0, about 320 ms floor).
- **MAVLink signing is not wired.** Every link is unsigned, and the app shows the "Unsigned link" chip and Diagnostics "Unsigned (no MAVLink signing): yes".
- **The RADIO-profile freshness window is still 3 s in Kotlin** (`VehicleState.FRESH_MS`, not per telemetry profile). With 0.5 Hz radio streams, one lost frame can mark telemetry stale (W3 deferral).
- **The real-hardware profile stays locked** (spec 8.4). This build is for the simulator only.
- Other items:
  - SessionControllerSitlTest's extra wall bound is flaky on this host (above). It failed both T15 runs and passed the review re-run. Follow-up: scale the margin by simulator speed.
  - Speech packs pushed with adb need their folder created first (`adb shell mkdir -p …/files/import/<pack id>`). Several-file `adb push` does not create it, and the app does not either (found in review on the QA AVD; the README shows the commands).
  - Pack import runs on the speech thread at voice start. Copying and hashing a ~200 MB CTC pack holds voice (including the voice STOP spotter) in LOADING for the whole copy. A stop → start during an import can run two imports into the same folder. Integrity holds, because files are re-verified before loading. Follow-up: make the import single-flight with a visible "importing" reason.
  - Real speech through the emulator microphone was not tested (digital zeros). The phone-side AudioRecord path with a real voice, Volume-Up PTT on hardware, and the Android 14+ microphone foreground-service rules on a phone remain unverified.
  - On the emulator, "Another app is using the microphone" is caused by the virtual microphone's digital zeros, not by another app.
  - The Models screen still says "Coming in the next update" for ta/kn/ml, although packs pushed into the import folder are now imported on Tier M/H phones. There is still no in-app download for the sherpa packs.
  - The first parse in each process costs 60-260 ms (class initialisation, T14). The parser is not warmed when speech loads.
  - `setEndpointerDelays` is not wired on the stop recognizer (T11 deviation 2). The segment-end final result now covers the late partial.
  - `check_android_package.py` still requires only the Vosk notice, not the three new notice files.
  - The minor T12 review items stay open: the PttBar release race, the microphone foreground-service fallback, the speech-thread snapshot load, and the stop counter on backgrounding.
