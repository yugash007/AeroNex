## Provisioning

Use an ARM64 Android phone with Android 8/API 26 or newer. There is no fixed available-RAM startup requirement. The app attempts to load the selected model and reports actual allocation failures. Android native recognition requires Android 12+ and a compatible installed service/language; Whisper works independently of that service.

Install 0.1.7 over the existing app and reopen it to retain its private model files. The emulator upgrade from 0.1.6 retained its models and speech settings. On launch, **Checking installed models…** becomes **Models ready** once verification completes. Saved verification flags are not required. An installed model replaces a missing selection automatically; installed selections are preserved. Ready rows offer **Manage**, missing required models offer **Set up**, and optional alternatives offer **Add**. Damaged files are labeled **needs repair**.

The screenshot errors `Can't obtain peer field ID for class com.sun.jna.Pointer` and `org.vosk.LibVosk` came from release optimization of JNA. Updating the app fixes that packaging problem; redownloading models does not. If Vosk initialization fails for another reason, **Speech engine needs attention** replaces general readiness, capture is disabled for that failed runtime, and **Use Whisper instead** switches to the alternative backend. Whisper uses its installed model or opens setup if missing. Typed interpretation remains available with the selected Local AI model. Technical details are in diagnostics. Reopen the app after an update so Android starts a fresh native runtime.

Use **Set up → Download**, or choose **Import … from a file** for an existing download. Required-model setup also opens when tapping a command with missing models. Downloads and imports verify byte count and SHA-256 before atomically replacing private model storage. Download progress and cancellation are shown in the app. No projector is needed. One Local AI model and one model for the selected speech backend are sufficient; the other variants are optional.

Choose **Vosk (offline)** with **Indian English**, **Telugu** or **Hindi** to use the matching pack. Each is a separate ZIP download/import; having Whisper or Whistle installed does not install Vosk. Only the selected language's Vosk pack is required. Its complete extracted tree is verified and a valid backup is recovered after an interrupted replacement. Explicit saved speech-backend choices survive updates. Without a saved choice, an installed matching Vosk pack is preferred, then installed Whisper. English uses `en-IN` and old `en-US` settings migrate. Telugu remains the first-install language. Tamil/Kannada/Malayalam/auto switch from Vosk to Whisper with an explanation because official Vosk packs are unavailable for them.

Vosk displays **Hearing** partial text while recording. English may offer **Use Vosk suggestion** in review; tapping it changes only the editor and preserves **Heard**. Unknown candidates and suggestions changing numeric/negation tokens are suppressed. Interpretation still requires its own tap. For mixed Telugu and English, try Whisper as an alternative: Vosk Telugu lacks Latin drone-command vocabulary and the upstream model reports 87.9 WER on Fleurs. No physical-phone accuracy measurements exist yet.

Whistle and Needle are optional. To try them, add both through **Models and device readiness**, choose **Whistle (English, offline)** as Speech backend and **Needle 3 (English tools)** as Local AI. Selecting Whistle sets English with an explanation. Choosing Telugu or another non-English language returns speech to Whisper; select LFM for non-English interpretation. Whistle's upstream seven-language list does not include Telugu, and this app integration currently exposes English only.

Whistle uses the same Finish/review flow and supplies drone vocabulary as recognition hints. Needle receives edited text only after **Interpret reviewed command**. The Cactus runtime retains one text and one speech model for the process lifetime and serializes calls. Cancelling invalidates results, but its C API cannot interrupt an active decode; the app waits for the bounded call before enabling another operation. Failed initialization requires restarting the app before retrying Cactus. The other backends remain available afterward.

For Telugu, use LFM Q4 for interpretation and compare Vosk Telugu with Whisper Base for speech. When using Whisper, installed Base is preferred unless a Whisper model was explicitly selected. Tiny remains the faster option. Changing the Local AI dropdown does not pin a Whisper choice. If a chosen Whisper model temporarily fails verification, an installed alternative can run; repairing the chosen file restores that preference. Language and backend survive app restart. Select Telugu for Telugu speech, or Indian English for fully English speech; explicit selection prevents auto-detection from picking the wrong language on short clips.

Close setup, tap **Speak a command**, and wait for **Listening** before speaking. The same button becomes **Finish recording** when capture is active. Tap it once; the app then shows **Transcribing**. Capture stops automatically after 15 seconds. Since 0.1.7, a fixed 480 KB buffer keeps Vosk decoding off the microphone reader and Finish drains all captured samples. Slow decoding may extend the Transcribing phase. Cancellation waits for active native decoding before closing the recognizer. Early/repeated/stale Finish requests do not interrupt another session. Very short clips and silence receive specific errors; the Speak button returns after a microphone failure so capture can retry.

The result appears in **Review transcript**. Edit misheard words, then tap **Interpret reviewed command** to request a local AI proposal. The original **Heard** text remains visible. Telugu-mode Arabic output is held for correction. The exact reported “headrooms slide” mishearing offers **Use “Hey drone, fly”**; apply it only if that was intended. “Fly” still requires an altitude, for example “take off to 3 meters.” Routine cleanup handles an initial “hey drone”, takeoff/take off, metres/meters and simple number words near units; it does not silently guess a different action.

Whisper releases its context before LFM loads. Typed commands need the selected Local AI model only. Speech capture and the isolated microphone test need the selected speech model only; Local AI readiness is checked when interpreting the reviewed command. Tap-to-talk is intentional; no wake-word service exists. Whisper's decoder was not replaced, and actual Telugu accuracy needs device evaluation.

For **Android on-device** speech, select a specific language and tap **Check Android language**. On Android 13/API 33+ the app checks installed/pending/supported offline languages when the service allows it. Error 13 means the language is supported but currently unavailable, often because its pack is missing; **Download Android language** requests installation. Android 14+ can report download completion when the service supports it. A scheduled/requested download is not shown as installed. On Android 12 or services without these APIs, use **Speech settings**, or **Use Whisper instead**. No online-recognizer fallback is used.

Start in dry-run mode, the default. Read the transcript and every plan step with its **Rules** or **AI** label. One confirmation covers the whole plan and expires after 15 seconds. An incorrect proposal must be cancelled; there is no guarantee a 450M model correctly interprets every language or negation.

## Simulator setup

Development MAVLink is unsigned, with strict configured IP/UDP port and system/component 1/1 filtering. Use a trusted isolated simulator network, never real hardware. The implementation currently accepts quadrotor heartbeat type only.

Configure SITL/MAVProxy to receive phone packets on the remote port and send telemetry back to the phone's local port. Defaults in the phone UI are remote 14550 and local 14551. Bind addresses must be reachable over the LAN. A GCS heartbeat alone is not enough: **Connect** waits for a fresh vehicle heartbeat and then requests telemetry itself; **Request telemetry** repeats the request. The simulator card shows the heartbeat state, and the status card shows a readable vehicle line. SITL mode, the address and both ports are saved and reused at the next launch. Missing position, battery, health or landed-state messages block relevant commands.

The separately tested executor implements GUIDED → ordinary arming (no force/bypass) → takeoff and checks altitude/landed state. Movement uses a single LOCAL_NED position target, transformed from drone-relative direction. LAND uses mode 9, HOLD uses BRAKE mode 17. These mappings passed the recorded shared-codec host/SITL check; they still require full phone testing. Unknown ACK/outcome locks further execution until the operator inspects the simulator and reconnects; reconnect never replays an old command. Since 0.2.0 the screen sends confirmed plans to this executor only while **Execute confirmed commands in simulator** is on for the current connection. Steps run one at a time, each waiting for telemetry to confirm completion, and the plan stops at the first REJECTED or UNKNOWN step. Reconnecting, disconnecting, toggling SITL mode or backgrounding returns to dry run.

The development session must not transmit to real flight hardware. A simulator switch is a user acknowledgement, not peer authentication.

## Reproducible checks

- `flutter test`, `flutter analyze`, and both `flutter build apk --debug --target-platform android-arm64` and `flutter build apk --release --target-platform android-arm64`.
- Run `tools/check_android_package.py` against each final APK, using the expected version, certificate and SDK build-tools as shown in the implementation README. This validates the actual DEX/JNI contract after R8, plus identity, signing and native packaging. Debug/JVM tests alone cannot detect release-only renaming.
- `tools/check_local_model.py`: text-only LFM smoke check against a locally started llama-server; prints proposals, never executes tools. This is not a test of JNI or mobile speed.
- *Historical (up to 0.2.0; 0.3.0 removed the native codec, `check_mavlink_native` and `check_sitl.py --codec`; `check_sitl.py` is now pymavlink-only and the Kotlin link is tested by the JVM SITL suite):*
- `tools/check_mavlink_native.cpp` via CMake/CTest: exercises the same native codec as Android JNI with generated wire frames, including EKF readiness and invalid frames.
- `tools/check_sitl.py --codec <compiled-check-mavlink>`: starts a fresh simulator subprocess on an ephemeral loopback port, checks telemetry plus takeoff/move/hold/completed landing using the shared codec, and stops only its own processes. It is not the full phone integration test. Without `--codec`, it retains the narrower legacy pymavlink compatibility check.

Neither a successful APK build nor host tests certify flight safety. Dry run remains the default. Turn on simulator execution only with an isolated SITL instance while actual native model behavior and the complete phone-to-SITL flow are being verified, and never with a real aircraft.
