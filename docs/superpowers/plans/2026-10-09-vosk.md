# Vosk Integration Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement the independently reviewable tasks below. Keep the existing uncommitted app work intact.

**Goal:** Integrate offline Vosk with Indian English, Telugu and Hindi packs and verify recording and model readiness behavior.

**Architecture:** Extend the verified model store to safely install multi-file Vosk packages. Add a streaming speech adapter behind the existing platform channel and recorder; connect Flutter selection, setup and partial text to it.

**Tech Stack:** Flutter/Dart, Kotlin, Android AudioRecord, Vosk Android 0.3.75, JNA, Python host evaluation.

**Spec:** `docs/superpowers/specs/2026-10-09-vosk-design.md`

## Global Constraints

- Preserve all existing uncommitted work; no commits, resets, pushes or merges.
- Android ARM64, minimum API 26, 16 kHz mono PCM16 capture, maximum 15 seconds.
- No fixed 2 GiB free RAM gate. All flight confirmations remain dry runs.
- English UI locale is `en-IN`; accept legacy `en-US` inputs.
- Vosk covers English, Telugu and Hindi. Tamil, Kannada, Malayalam and auto use Whisper.
- Pinned model archives and every extracted model file require size and SHA-256 verification.
- Source downloads are official HTTPS; cancellation and invalid replacements preserve working installations.
- Existing transcript review precedes interpretation; unknown or blank recognition cannot dispatch commands.

### Task 2: Streaming speech, language selection and setup

**Interfaces:** platform method `vosk` accepts the same `language` and `sessionId` fields as `whisper` and returns `text`, `language`, and optional `suggestion`. `speechStatus` additionally exposes `partialText`. Reuse Task 1's language/profile lookup and `runtimeFile`. Hold `LocalModelDirectoryLocks.forDirectory(directory).readLock()` on the worker for the whole Vosk model session. Add an injectable streaming recognizer factory to `LocalInferenceBridge` so microphone, cancellation and cleanup can be tested without loading ARM64 binaries on the host. Add an optional named `suggestion` to the existing Dart `Transcript` type; existing positional calls stay compatible.

```kotlin
interface StreamingSpeechRecognizer : AutoCloseable {
    fun accept(samples: ShortArray, count: Int): String
    fun finish(): String
    val suggestion: String? get() = null
}
```
